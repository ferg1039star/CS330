I start by breaking the requirement into the smallest pieces that still do something visible. For the 3D scene that meant listing every object in the photo and naming the primitive that would stand in for it: boxes for shelves and books, a tapered cylinder and torus for the mug, a cylinder and torus for the watch. I write the transforms for one object, get it on screen, then copy the pattern. The new skill was learning to treat layout, texture, and lighting as separate passes instead of trying to finish one object completely before moving to the next. I followed the same process on the collision assignment: get circles moving with velocity, then add wall bounce, then brick hits, then circle-to-circle. In future work I will keep that order. A working skeleton is easier to extend than a half-finished piece that already has every feature tangled together. I write the smallest change that should produce a visible result, build, and look. On the nightstand that meant placing one shelf, then the legs, then the mug, and only after that adding textures and lights. Iteration showed up every time something looked wrong. The mug handle washed out because the torus caught too much specular, so I gave it a duller material. The back wall went black at the top, so I gave it its own ambient. Pages turned black because they inherited the previous material, so I set a paper material on every page draw. Early milestones used one color and no camera. Later ones added input, then textures, then lights. By the final scene the same draw pattern handled every object, which is why adding the watch and frame at the end was fast. That is the strategy I will keep: one clear loop for setup, one clear loop for draw, and materials and textures stored by tag so a change in one place updates every use. Computational graphics forced me to think about state, transforms, and the order of operations in a way that transfers to any interactive program. Knowing how a camera, a projection matrix, and a shader uniform fit together is useful for game tools, simulation, and any UI that has to show spatial data. On the professional side, the same habits (modular functions, reusable materials, incremental builds) apply to the applications I want to build after the degree. The course did not teach a game engine, but it showed why engines hide the matrix math and the lighting model. That makes it easier to use those tools later without treating them as black boxes.
